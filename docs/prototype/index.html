Sakina Prototype

A quiet app so the conversation can be loud. Click through every screen, at any of six real device sizes, in all three languages.

This is a design prototype, not the app. It is HTML rendering the same palette, strings and layout rules the Flutter client uses — so what you see is accurate — but the Flutter app has never been compiled, because there is no Flutter SDK in the environment it was built in. Running it for real

Three ways, in increasing order of effort and fidelity.

1. The browser client — two real people chatting, in about a minute

This is the one worth doing first. It is a real client speaking the real protocol to the real server: sign-in, sockets, idempotent retries, offline catch-up. No Flutter, no emulator, no phone. 

git clone https://github.com/HNM16/Sakina && cd Sakina
pnpm install
pnpm infra:up        # postgres + redis + minio, via Docker
pnpm build
pnpm db:migrate
pnpm dev             # api :4000, gateway :4001, worker :4003

# in a second terminal
pnpm dev:client      # http://localhost:4002

Open localhost:4002 in two tabs, sign in with two different email addresses (the code is returned in the response — no mail server needed), copy one tab's user id into the other, and talk. Kill the gateway mid-conversation and watch the messages queue and then arrive.

2. The test suites — the fastest verdict

pnpm test          # 125 checks
pnpm test:devices  # the layout at 31 real device sizes, in a real browser
CommandChecksWhat it proves
test:auth15Every Gmail and Yandex variant lands on one account; disposable domains refused; one device cannot farm accounts
test:bans10A banned user with a new email on the same handset is refused
test:messaging24A retried send whose ack was lost does not duplicate; an offline client catches up
test:push17A closed app is notified; an open one is not; no message text in the payload
test:social48A channel subscriber is refused at every entry point; a stolen media key is rejected; HTML and SVG uploads refused
test:l10n7Every string in three languages; every key the UI asks for exists
test:dart4Imports resolve, brackets balance, no undefined Sakina symbols
test:devices16The layout at all 31 device widths, including a real browser at each viewport

The suites assert real limits, so the server has to be running with the limits they assert. test:auth checks that one device cannot farm accounts, which means the per-device cap must be at its default — while the same suite creates a dozen accounts from one address, so the per-IP ceiling has to be lifted: 

MAX_SIGNUPS_PER_DEVICE=3 MAX_SIGNUPS_PER_IP=1000000 \
OTP_RESEND_COOLDOWN_SECONDS=0 TEST_IDENTITIES="qa@sakina.tj:000000" \
STORAGE_PROVIDER=local pnpm dev

3. The Flutter app — the real client, and the honest caveat

Every screen in this prototype exists as Dart in apps/mobile. None of it has ever been compiled. That is not a figure of speech: there is no Flutter SDK in the environment this was built in, so the code is read-checked and machine-checked but never once run. 

cd apps/mobile
flutter create .          # generates android/ ios/ — they are gitignored
flutter pub get
flutter run --dart-define=API_URL=http://10.0.2.2:4000 \
            --dart-define=WS_URL=ws://10.0.2.2:4001/ws

10.0.2.2 is how the Android emulator reaches your host machine; on an iOS simulator use localhost, and on a real handset use your computer's LAN address. Expect compile errors on the first run — that is the whole point of the caveat, and fixing them is the next real task. flutter analyze before flutter run will find most of them in one pass.

The palette

From apps/mobile/lib/src/theme.dart. Firuza is the glaze on Samanid tilework; it is the only accent.

Saffron is for rare warmth — an admin badge, a channel handle. Pomegranate appears only when something is lost. A screen with three accent colours has none.
